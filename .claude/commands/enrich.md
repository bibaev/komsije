# /enrich — обогатить новые бизнесы

Таблица инициативы растет каждый день, а сборка показывает новый бизнес сразу, но с угаданной категорией и описанием из таблицы, а часто и без точки на карте. Этот скилл доводит такие бизнесы до вида остальных: запись в `data/overrides.json` и PR. **Мержит владелец репо** (`main` защищен), скилл не мержит.

Граница из `CLAUDE.md`: данные бизнеса (название в таблице, адрес, контакты, включение в список) правятся только в таблице инициативы. Здесь — только слой обогащения.

## Шаг 0. Свежий main и ветка

```bash
git checkout main && git pull --ff-only && git checkout -b data-$(date +%Y-%m-%d)
```

Ветка с таким именем уже есть — добавить суффикс `-2`, `-3`.

## Шаг 1. Что осталось

```bash
.venv/bin/python -m komsije.todo --geocode
```

Два списка:
- **нужна запись в overrides.json** — номер, название из таблицы, описание из таблицы, угаданная категория, какие есть ссылки;
- **адреса без точки** — адрес дословно как в таблице (в кавычках, может быть смесь кириллицы и латиницы) и предложение из OpenStreetMap: «надежно», «проверить» или «не нашел».

Пусто — сказать «все обогащено» и остановиться.

## Шаг 2. Запись на каждый бизнес

Ключ — номер MB или ПИБ из списка. Новые записи — в конец файла, в формате соседних (две-четыре строки на запись, тот же порядок ключей). Примеры — уже существующие записи.

| Поле | Когда | Как |
|---|---|---|
| `name` | в таблице юрформа или шум | «… PR», «PR Novi Sad», «d.o.o.», подзаголовок → бренд, если он виден в названии или ссылках бизнеса (`Service Power ILIA KACHAROVSKII PR` → `Service Power`); бренда нет, фирма на имя человека → «Имя Фамилия» без PR (`Albina Popovkina`). Бренд не придумывать |
| `categories` | всегда | 1–2 id из `data/categories.json`; первая — главная, ее значок стоит на карте. Спорные случаи: компьютерный клуб → `kultura`, коворкинг → `uslugi`, цветы и украшения → `podarki`, растения и чай → `magazin`, тату и пирсинг → `krasota`, кафе-выпечка навынос → `eda`, ресторан с залом → `restorany` |
| `description_ru` | всегда | одна короткая фраза по сути из описания в таблице: что делают и для кого. Без оценок («лучший», «уютный») и без фактов, которых нет в таблице |
| `description_sr` | только если в таблице описание по-английски, по-русски или с опечатками | исправленная фраза на сербской латинице; иначе поле не пишется и берется описание из таблицы |
| `tags` | всегда | 1–3 тега `ru` и `sr`, строчными, кроме имен собственных и аббревиатур (`IELTS`, `Apple`) |
| `points` | адрес без точки | см. ниже |
| `no_point` | искали и не нашли | список адресов дословно; они уходят из списка дел и из предупреждений сборки |
| `hidden` | только по просьбе самого бизнеса | причина и дата строкой, без личных подробностей |

**Точки** — по порядку, первое подходящее:
1. «надежно» из `komsije.todo` — взять строку `"points"` как есть: в ней адрес уже записан дословно.
2. «проверить» или «не нашел» — открыть ссылку Google Maps из таблицы в браузере и взять координаты из адреса страницы (`!3d…!4d…` или `@широта,долгота`), если страница показывает именно этот бизнес. У «проверить» из OpenStreetMap можно взять точку, если в найденном адресе та же улица и тот же номер дома (например, дом записан диапазоном). Исключение — «проверить, таких домов в городе несколько»: тут только Google Maps, первой OpenStreetMap может отдать не ту улицу (так было с «Jug Bogdanova 8»: центр и Винча).
3. Ничего не подошло — адрес в `no_point`. **Неправильная точка хуже, чем никакая.**

Адрес-ключ копировать только из вывода `komsije.todo`, не набирать руками: в таблице бывают латинская «K» среди кириллицы и опечатки, и точка с неточным ключом молча не встанет.

## Шаг 3. Проверить

```bash
.venv/bin/python -m komsije.build          # в предупреждениях не осталось новых бизнесов
.venv/bin/python -m komsije.todo           # в списке дел только то, что осознанно оставлено
.venv/bin/pytest -q && .venv/bin/ruff check .
```

Предупреждение «в overrides.json адрес, которого нет в таблице» — ключ точки набран не так, как в таблице: исправить ключ.

## Шаг 4. PR

```bash
git add data/overrides.json data/geocache.json
git commit -m "Add N newly verified businesses"
git push -u origin HEAD
gh pr create --base main --title "Add N newly verified businesses" --body "…"
```

В описании PR: сколько бизнесов в проверенной вкладке; список новых с категорией; откуда точки (OpenStreetMap, Google Maps); какие адреса ушли в `no_point`; спорные категории — отдельной строкой, чтобы владелец мог поправить. Дождаться зеленой проверки (`gh pr checks --watch`) и отдать ссылку на PR владельцу.

После мержа сайт пересобирается сам; браузер может держать старую версию до 10 минут (кэш GitHub Pages).
